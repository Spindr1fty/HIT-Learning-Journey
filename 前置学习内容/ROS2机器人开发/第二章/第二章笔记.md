3. 完成ROS2的第一个节点的编写及运行
```cpp
#include <rclcpp/rclcpp.hpp>
#include <iostream>
using namespace std;
int main(int argc,char** argv)
{
    // : 为域名解析符
    rclcpp::init(argc,argv);
    //auto为自动类型推导,在此创建一个rclcpp下的node的共享指针
    auto node = std::make_shared <rclcpp::Node> ("cpp_node");

    RCLCPP_INFO(node.>get_logger(),"你好，C++节点");
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

## 2.3 使用功能包组织C++节点
1. 在Ubuntu中打开VScode并打开集成终端，使用`ros2 pkg create --build-type ament_cmake --license Apache-2.0 demo_cpp_pkg`命令来创建工具包,在目录 > Chapt2 > demo_cpp_pkg 下有一个CMakeLists.txt文件，其原因为C++版本的功能包其编译过程其实也是调用CMake进行构建，创建完成后就可以编写代码，在 > src 文件夹目录下新建 cpp_node.cpp 文件，把2.1.2中 ros2_cpp_node.cpp 的代码复制到新建的文件中即可。  
2. 对功能包进行配置
在最终构建时，需要在CMakeLists中进行指定，把2.1.2中的指定代码复制到其# find_package下面  
```bash
//2.1.2中指定代码
add_executable(ros2_cpp_node ros2_cpp_node.cpp)

find_package(rclcpp REQUIRED) # 直接查找到对应的头文件和库文件
message(STATUS ${rclcpp_INCLUDE_DIRS}) #头文件及rclcpp依赖的头文件
message(STATUS ${rclcpp_LIBRARIES}) #库文件及rclcpp依赖的库文件

target_include_directories(ros2_cpp_node PUBLIC ${rclcpp_INCLUDE_DIRS}) #连接头文件
target_link_libraries(ros2_cpp_node ${rclcpp_LIBRARIES}) # 链接库文件
```
并改名字：  
 - `add_executable(ros2_cpp_node ros2_cpp_node.cpp)` 更改为`add_executable(cpp_node src/cpp_node.cpp)`#src是因为当前的CMakeLists是相对目录
 - `target_include_directories(ros2_cpp_node PUBLIC ${rclcpp_INCLUDE_DIRS}) `更改为`target_include_directories(cpp_node PUBLIC ${rclcpp_INCLUDE_DIRS}) `
 - `target_link_libraries(ros2_cpp_node ${rclcpp_LIBRARIES}) # 链接库文件`更改为`target_link_libraries(cpp_node ${rclcpp_LIBRARIES}) # 链接库文件`  
 鉴于每次要写一堆包含目录和链接库的代码，为了方便可使用一个简单的命令：`ament_target_dependencies(可执行文件名 依赖名)`在当前目录下为`ament_target_dependencies(cpp_node rclcpp)`
 完成后就可以进行构建功能包，使用`cd ..`返回上一级直到进入主目录，再使用` colcon build `进行构建，构建完成后在 > Chapt2 > demo_cpp_pkg > build > demo_cpp_pkg 下出现 cpp_node 文件，右击在集成终端中打开，用 `ls` 查看当前目录下的文件会发现有 cpp_node ，最后使用  `./cpp_node` 进行运行  
 `ldd cpp_node`命令可以查看cpp_node依赖哪些库，并且这些库是否正确连接
现在回到主目录，运行`ros2 run demo_cpp_pkg cpp_node`会出现 Package 'demo_cpp_pkg' not found ，是因为环境变量 AMENT_PREFIX_PATH 没有加到 > Chapt2 > install > demo_cpp_pkg > lib ，在集成终端中使用命令`sourece install/setup.bash`来自动修改环境变量，修改完之后再次在终端中使用`printenv | grep AME`命令查看环境变量会发现有环境变量 AMENT_PREFIX_PATH=/home/spindrift/Chapt2/install/demo_cpp_pkg:/opt/ros/humble ，再次运行`ros2 run demo_cpp_pkg cpp_node`即可运行

## 2.5.1面向对象编程C++示例
- 面向对象编程  
与C语言面向过程的编程不同，面向对象编程都可以创建类，类是对事物的封装，事物可以是人，手机，机器人等任何事物，都可以封装成一个类，类可以拥有自己的属性和方法，比如人类，属性是姓名、身高、年龄；方法是吃饭、睡觉、做运动。总体来说是定义一个类，然后用类去产生一个对象，再去调用它的方法实现各种各样的功能，在使用继承创建一个新的类的时候会更省事，比如创建一个新的作家类，可以直接在人类上进行继承并加入新的方法
1. 打开VScode，并打开集成终端，进入Chapt2_ws，创建一个 personode 并通过继承 rclcpp 中的node来实现创建一个节点  
在 > Chapt2 > Chapt2_ws > src > demo_cpp_pkg > src路径下新建  person_node.cpp  
2. 因为是要继承rclcpp，所以第一步先导入这个库：`#include <rclcpp/rclcpp.hpp>`  
3. 在CMakeLists里添加可执行文件
```bash
add_executable(person_node src/person_node.cpp)
ament_target_dependencies(person_node rclcpp)
install(TARGETS cpp_node person_node
  DESTINATION lib/${PROJECT_NAME}
)
```
4.编写代码
```cpp
#include <rclcpp/rclcpp.hpp>
using namespace std;

class PersonNode : public rclcpp::Node  //定义一个PersonNode类让其继承于node
{
//添加属性，在C++中有私有成员，公共成员和保护成员这样区分
//声明
private:  //私有成员
    std::string name_;
    int age_;
public:  //添加完属性,构造函数在C++里面就要跟类的名字一模一样，没有任何返回值
    PersonNode(const std::string &node_name,const std::string &name,const int &age)
    :Node(node_name)  //因为我们继承到这里还有一个额外的要求，要求调用父类
    //传入之后要把它赋值到类内部的属性里面去
    {
        this->name_ = name;
        this->age_ = age;
    };
    //const作用是不希望用户在函数内做修改
    void eat(const std::string & food_name)  //方法
    {
        RCLCPP_INFO(this->get_logger(),"我是%s,%d岁,爱吃%s",this->name_.c_str(),this->age_,food_name.c_str());
        //C++版本:  (this->get_logger(),"我是" <<this->name_ << "," << this->age_ << "岁，爱吃" << food_name);
        //用这个类跟用cpp_node方法一样
    };
};


int main(int argc,char** argv)
{
    rclcpp::init(argc,argv);
    auto node = std::make_shared<PersonNode>("person_node","李斯",18);
    RCLCPP_INFO(node->get_logger(),"Hello");
    //此处node是一个指针
    node->eat("鱼香肉丝");
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```
5.在VSCode的集成终端中使用命令`colcon build`进行构建，并用`sourece install/setup.bash`来自动修改环境变量  
6.最后使用`ros2 run demo_cpp_pkg cpp_node`运行  

## 2.5.2用得到的C++新特性
- 在正式深入学习ROS2之前，学习一点用得到的C++新特性，例如在前面的小节中，实例化ROS2节点的时候使用了一句命令：  
auto node = std::make_shared<rclcpp::Node>("cpp_node");  
这一句代码中就包含了两个重要的C++新特性：  
第一个是自动类型推导，就是这里为什么我们可以使用auto，auto就是自动类型推导，node的类型根据右边的部分自动推导左边的node的类型，所以node的类型不是auto，auto只是一个形容词来修饰node这个语法  
第二个新特性是智能指针，make_shared这个函数它可以传入一个模板类然后再传入这个参数，最后可以创建出一个指针  
- 自动类型推导：

- 智能指针：  
智能指针是在C++ 11版本引用的一种智能化的指针，它可以管理动态分配的内存，避免内存泄漏和空指针问题，C++ 11提供了三种类型的智能指针，分别是： unique_ptr 、 shared_ptr 、 weak_pdr 在此重点介绍 shared_ptr  
#️⃣其实就是一个堆区，正常C++里用 new 开辟，用完需要手动释放，这里用 shared 开辟用完可以自动释放

如果在同一个程序中，将某一个资源使用智能指针进行管理，无论是拷贝、分享，最终的内存地址不会改变，说明没有进行内存拷贝，这样进行数据传递的时候效率较高，无论在多少个函数内进行传递，都不会发生资源的复制，运行效率得以提高，同时当所有的程序都使用完这个内存地址之后，它还能自动的去回收，不会造成内存泄漏。这也是在ROS2中大量采用智能指针的原因  
- Lambda表达式
Lambda表达式其实是C++中的一种匿名函数，它是没有名字的但是可以像正常的函数一样去调用，Lambda表达式有一套自己的语法规则，其格式为：`[capture list](parameters) -> return_type {function body}`，其中`[capture list]`称为捕获列表，`(parameters)`称为函数的参数列表，`-> return_type`指向的是返回值，`{function body}`是函数体。

- 函数包装器

```cpp
void save_with_free_fun(const std::string &file_name)
```

```cpp
class FileSave
```


要点:**功能包必须放在 `工作空间/src/` 下**;工作空间根目录里不要放 `CMakeLists.txt`,否则 colcon 会把根目录误认成一个包。

## 二、标准开发流程(牢记这四步)

```bash
cd ~/Chapt2/Chapt2_ws
source /opt/ros/humble/setup.bash   # 给 ROS2 打底(通常 .bashrc 已做)

# ① 写代码 / 改 CMakeLists.txt
```

**`colcon build` 只负责编译和生成 `install/`,不会自动加载环境;`source install/setup.bash` 才是让 `ros2` 找到你包的动作。**

## 五、踩坑清单(报错 -> 原因 -> 解决)

### 1. `Package 'demo_cpp_pkg' not found`

两种原因分别对应:

- **没 source 环境**(最常见,新开终端必现):

  ```bash
  source ~/Chapt2/Chapt2_ws/install/setup.bash
  ```

  验证:`echo $AMENT_PREFIX_PATH`,应看到 `.../Chapt2_ws/install/demo_cpp_pkg:/opt/ros/humble`。

- **包不在 `src/` 下**(或没构建过):确认包路径是 `Chapt2_ws/src/demo_cpp_pkg`。

> 区分技巧:报 **Package** not found = 环境/包的问题;报 **No executable found** = 包找到了,是**可执行名写错**。

### 2. `colcon build` 显示 `Summary: 0 packages finished`

- **原因**:工作空间根目录里有遗留的 `CMakeLists.txt`(以及 CMakeCache 等),colcon 把根目录误当成一个包,就不再进 `src/` 找包。
- **解决**:把这类旧文件移走/删除,保证根目录只有 `src/ build/ install/ log/`。
- **验证**:`colcon list` 应显示 `demo_cpp_pkg  src/demo_cpp_pkg  (ros.ament_cmake)`。

### 3. build 成功,但 `install/.../lib/...` 下没有可执行文件

- **原因**:漏了 `install(TARGETS ...)`。
- **解决**:把新目标加进 `install(TARGETS ...)` 列表,重新 `colcon build`。

### 4. 可执行名对不上(运行 `learn_shared_ptr` 找不到)

- **原因**:`ros2 run <包名> <可执行名>` 里的可执行名,由 `add_executable(名字 ...)` 的**第一个参数**决定,和源文件名不一定一样。
- **解决**:用 `ros2 pkg executables demo_cpp_pkg` 查真实名字;想让名字统一就改 `add_executable` 和 `install` 两处。

### 5. `warning: variable 'print_sum' set but not used`

- **原因**:lambda 只**定义**没**调用**。
- **解决**:在定义后加调用 `print_sum();`;只是练习可忽略。

### 6. `warning: statement has no effect`(写成了 `print_sum;`)

- **原因**:调用函数/lambda 必须带圆括号。
- **解决**:`print_sum;` -> `print_sum();`
- **口诀:定义用 `=` 存起来,执行必须加 `()`。**

### 7. `bind` 绑错函数 -> 程序"没反应"/线程爆炸

```cpp
auto f = bind(&Download::start_download, this, ...);  // 错:绑成自己 -> 无限递归创建线程
auto f = bind(&Download::download,      this, ...);   // 对:绑真正干活的函数
```

### 8. `error: expected unqualified-id before '.' token`(`thread.detach()`)

- **原因**:变量名写成了**类型名** `thread`。

```cpp
thread t(download_fun, ...);   // 第一个 thread 是类型,t 是变量名
t.detach();                    // 操作时必须用变量名 t
```

> VS Code 里改名用 **`F2` 重命名符号**,可避免"改一处漏一处"。

### 9. 下载程序没输出"下载完成..."

- **原因**:HTTP 请求失败,`response->status != 200`,回调不执行。常见是:
  - 被下载的文件**不在 `python3 -m http.server` 启动时所在目录**里 -> 404;
  - host 写成了 `http://0.0.0.0:8000`(那是"监听地址",客户端连接要用 `http://127.0.0.1:8000`)。
- **解决**:

  ```bash
  cd ~/Chapt2/Chapt2_ws          # http.server 的服务目录
  echo '第一本小说的内容 hello world 123' > novel1.txt
  curl http://127.0.0.1:8000/novel1.txt   # 先自己验证能取到
  ```

- **习惯**:给 `if` 加 `else` 打印失败原因,别让程序静默失败:

  ```cpp
  else {
      cout << "下载失败: " << path
           << " status=" << (response ? to_string(response->status) : "连接失败/无响应") << endl;
  }
  ```

### 10. shell 命令报"未找到命令"、还留下空文件

- **原因**:`printf'...'` 少了空格 -> shell 把 `printf` 和引号内容粘成一个命令名。
- **解决**:

  ```bash
  printf '内容\n' > novel1.txt      # printf 后有空格
  echo '内容' > novel1.txt          # 或用 echo 更简单
  ```

  注意 `>` 重定向会**先创建/清空文件**,所以即使命令写错,也会留下空文件。

### 11. VS Code 按 `F5` 报 `bits/c++config.h: 没有那个文件或目录`

- **原因**:F5 走的是 **CMake Tools 扩展**,它和 colcon 抢同一个 `build/` 目录、且环境与终端不同,不是代码问题(终端 `colcon build` 正常)。
- **解决**:学 ROS2 阶段**别用 F5**,只把 VS Code 当编辑器,构建运行都在终端;进阶再配 `tasks.json` + `launch.json`,并从"已 source ROS 的终端"里 `code .` 启动 VS Code。

### 12. 删了 `build/ install/ log/` 要恢复吗?

- **不用**。这三个是**构建产物**,删了下次 `colcon build` 会重新生成,源码从不放在这里。删之前确认自己的 `*.cpp` 都在 `src/` 下即可。

### 13. 目录重组后"源码不见了"

- **原因**:把 `src/demo_cpp_pkg` 移进 `Chapt2_ws` 时,目标位置已有**同名文件夹**(且里面是构建产物),粘贴被合并/中断,源码其实还在原处。
- **解决**:整理目录前先 `find . -name package.xml` 确认真正的包在哪(`package.xml` + `CMakeLists.txt` + `*.cpp` 齐全的才是源码包)。

## 七、每个文件讲什么、有什么用

### 包级文件

- **`package.xml`**:包的"身份证",声明包名、依赖、构建类型;colcon 靠它识别这是不是一个 ROS 包(缺了它就报 0 packages)。
- **`CMakeLists.txt`**:构建说明书,决定怎么编译/链接/安装;每加一个节点要同步改 `add_executable`、`ament_target_dependencies`、`install(TARGETS)` 三处。
- **`include/`**:放头文件;里面的 `cpp-httplib/` 是第三方纯头文件库,配合 `include_directories(include)` 才能 `#include <cpp-httplib/httplib.h>`。

### 源文件

- **`cpp_node.cpp`**:最小 ROS2 节点,演示 `init → 建 Node → RCLCPP_INFO → spin → shutdown` 五步,是所有 ROS2 C++ 程序的模板。
- **`person_node.cpp`**:用类继承 `rclcpp::Node` 来写节点,演示构造函数初始化成员和方法调用,是真实项目的常用写法。
- **`learn_auto.cpp`**: `auto` 自动类型推导,ROS2 里到处用 `auto node = ...`,省得手写长类型。
- **`learn_shared.cpp`**:智能指针(包括unique_ptr,shared_ptr,weak_ptr,此处重点解释shared_ptr) `std::shared_ptr` 的引用计数(`use_count`)与自动释放内存,ROS2 的节点和消息都用它管理。
- **`learn_lambda.cpp`**: lambda表达式 的定义、捕获(`[sum]`/`[&]`)和调用;ROS2 回调大量用它,记住"定义用 `=`,执行要加 `()`"。
- **`learn_functional.cpp`**:函数包装器用 `std::function` + `bind` 把自由函数、成员函数、lambda 统一成同一种调用方式,是 ROS2 把成员函数当回调的基础。
- **`learn_thread.cpp`**:综合练习——用 `std::thread` 起线程、httplib 下载文件、用回调处理结果,是 ROS2 多线程回调的雏形。
